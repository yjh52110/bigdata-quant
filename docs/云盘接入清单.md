# 云盘接入清单

照顺序做,每步都有验证方法。做完之后 Colab 和 Kaggle 都能把数据写进你的云盘。

前置结论(已实测,不用重新验证):

- `drive.mount()` / `colab drivemount` **走不通** —— 需要网页端授权弹窗,headless 下报
  `ValueError: mount failed`。Colab 官方仓库 `colabtools#4182`「让 mount 支持 Secrets」至今 open。
- Kaggle **根本没有挂载功能** —— `google.colab.drive` 是 Colab 专有模块,在 Kaggle 里 `KeyError`。
- **Drive REST API 是唯一两边都能用的路**。从 Colab 实测 33.8ms 返回 401(链路通、仅缺令牌)。

所以下面全部围绕"拿到一个 refresh token,放进平台的 Secrets"。

---

## 第 1 步:建 OAuth 客户端

1. 打开 https://console.cloud.google.com/ ,建一个项目(或用现成的)。
2. **API 和服务 → 启用 API → 搜 Google Drive API → 启用**。
3. **API 和服务 → OAuth 同意屏幕**:
   - 用户类型选 **外部**
   - 应用名、支持邮箱随意填
   - **范围**:只加 `https://www.googleapis.com/auth/drive.file`
     > 千万不要加 `.../auth/drive`。那是受限范围,发布到生产状态要先通过 Google 的
     > CASA 安全评估(周期性、收费、数周周期)。`drive.file` 非受限、免审计,而本项目
     > 只读自己写的文件,够用。代码里已经写死为 `drive.file`。
4. **凭据 → 创建凭据 → OAuth 客户端 ID**:
   - 类型:**Web 应用**
   - 已获授权的重定向 URI 填:`http://localhost:8000/api/accounts/oauth/callback`
     (若部署到公网主机,换成 `https://你的域名/api/accounts/oauth/callback`,并把
     后端的 `PUBLIC_BASE_URL` 设成同一个域名)
5. 下载 JSON,存成 `backend/data/credentials.json`(覆盖首次运行自动生成的占位文件)。

**验证:**

```bash
python3 -c "import json;b=json.load(open('backend/data/credentials.json'));b=b.get('web') or b.get('installed');print('client_id:',b['client_id'])"
```

打出来不是 `dummy_client_id` 就对了。

---

## 第 2 步:把同意屏幕发布到生产状态

**这步不做,后面全白搭。** 在 Testing 模式下:

- refresh token **7 天过期**,每周都要重新授权
- 只能连手工登记的约 100 个测试账号

OAuth 同意屏幕页面上点 **发布应用**。因为范围里只有 `drive.file`(非受限),不需要提交审核,
点完立即生效。

**验证:** 同意屏幕页面顶部状态显示 **生产中 / In production**。

---

## 第 3 步:连一个账号试

1. 启动后端和后台:

```bash
QUANT_API_KEY=你的密码 uvicorn backend.api_server:app --host 127.0.0.1 --port 8000
```

2. 后台 → **谷歌账号** → 添加账号,标识填 `acc-01` → 前往谷歌授权 → 选账号 → 允许。
3. 回来后账号列表应显示邮箱和已用/总容量。

**先连 1 个,别一次连 100 个。** 跑通整条链路再批量。

**验证:** 账号那一行的容量数字是真的(来自 `about().get(storageQuota)`)。

---

## 第 4 步:导出密钥(你自己跑)

```bash
python3 scripts/export_drive_secret.py acc-01
```

它打印一行 JSON,含 `client_id` / `client_secret` / `refresh_token`。

> 这行东西等同密码,它能写入该账号下由本应用创建的文件。脚本不把它发往任何地方,
> 只打到你自己的终端。**由你本人粘贴进平台的密钥存储**,不要贴进聊天窗口、
> 不要写进 notebook 单元格、不要提交进 git。

脚本会拦住两种常见错误:`credentials.json` 还是占位文件、账号没有 refresh token。

---

## 第 5 步:放进两个平台的 Secrets

密钥名统一用 **`DRIVE_OAUTH_JSON`**(两边代码的默认值都是它)。

**Colab:** 左侧栏钥匙图标 → 添加新密钥 → 名称 `DRIVE_OAUTH_JSON`,值粘贴那行 JSON →
打开「笔记本访问权限」开关。

**Kaggle:** 打开任一 notebook 编辑器 → 右侧 **Add-ons → Secrets → Add secret** →
同名同值 → 勾选给当前 notebook 使用。

> 为什么不用服务账号:消费级谷歌账号(你那种 5TB 的 Google One / AI Pro)**不能**给
> Drive 挂服务账号,用户授权的 OAuth refresh token 是唯一能碰到那块存储的凭证。

---

## 第 6 步:验证 Kaggle 侧(一键)

先放 Kaggle API 令牌:kaggle.com → Settings → API → Create New Token,
存到 `~/.kaggle/kaggle.json`,然后 `chmod 600 ~/.kaggle/kaggle.json`。

```bash
kaggle quota
```

这条通了,后台 **Colab 算力** 页的 Kaggle 额度数字和派发按钮就同时活了。

然后在派发区选 **云盘连通性自检** → 派发。它会在 kernel 内实测:

- Drive 接口可达性与延迟
- OAuth 令牌端点可达性
- `kaggle_secrets` 是否可用
- `google.colab` 是否缺席(预期缺席)
- 到 `storage.googleapis.com` 的下行速度(可与 Colab 实测的 185.9 MB/s 对比)

**验证:** 任务变 `COMPLETE` 后点「取回产物」,`result.json` 里 `checks.drive_api.status`
是 `401`(无令牌时的健康应答)或 `200`。

---

## 第 7 步:跑一个真实入库任务

派发区选 **AWS 链上数据**,填 `eth` / `blocks` / 单日日期。

以太坊 `blocks` 单日只约 5 MB,几十秒跑完,用来验证整条链路而不浪费额度。
**不要**第一次就选 `traces`(单日约 2.6 GB)或 `transactions`。

**验证:** `result.json` 里应有:

- `days_written` 非空、`mb_per_s` 有数字 → 下载正常
- `drive.total_files` / `drive.mb_per_s` → **这就是欠了很久的那个数字:云盘实际写入速度**
- `drive.quota.usage` 相比之前变大 → 数据真的落进云盘了

Colab 侧同理:worker 启动时会打印 `Drive reachable as <邮箱> -- X GB used`,
每个 ingest 任务的结果里带同样的 `drive` 字段。

---

## 第 8 步:批量连账号

前面全部通了再做这步。逐个重复第 3 步,标识用 `acc-02`、`acc-03`……

每个账号都要单独导出密钥吗?**不用。** 一个账号的令牌够跑通计算;多账号的意义是
**扩存储**(每号 5TB,rclone union 聚合),不是扩算力。

> 算力这块别指望多账号:Colab FAQ 原文把
> `using multiple accounts to work around access or resource usage restrictions`
> 列为禁止行为;Kaggle 的 GPU 还要手机验证,一个手机号也验不了多少账号。
> **跨平台**分散(Colab 一份、Kaggle 一份)不违规,同平台多账号刷额度违规。

## 实测记录（2026-07-25，本机 + acc-01）

整条链路已跑通，数字如下：

| 项 | 实测值 |
|---|---|
| 换取 access_token | 成功 |
| 建目录（drive.file 范围下） | 4.25 s |
| 上传 20 MB | 38.37 s = **0.52 MB/s** |
| 云盘配额变化 | 1090.6 → 1110.6 MB（精确 +20.0 MB） |

### 机房侧实测（2026-07-25，Kaggle kernel，手机验证后）

| 项 | 实测值 |
|---|---|
| 到 Google 存储下行 | **324.5 MB/s** |
| 写入云盘上行（200 MB） | **36.56 MB/s** |
| 写入云盘上行（5.9 MB） | 1.53 MB/s ← 被请求延迟主导，勿用于规划 |
| 运行时 | 4 vCPU / 31.3 GB |

同一条代码路径，200 MB 与 5.9 MB 相差 24 倍：一个 8MB 分片的建会话 + PUT 两个往返就占满了
小文件的全部时间。**做容量规划只能用大块传输的数字**，并且写入云盘时应尽量合并成大文件。

0.52 MB/s 是本机家宽上行的真实上限，不是接口瓶颈——这正是本方案把入库放到
Colab / Kaggle 的原因：它们的机房上行比家宽高两个数量级（已实测 Colab 到
storage.googleapis.com 下行 185.9 MB/s、公网 AWS 129 MB/s）。等你把密钥放进
平台 Secrets 后，派发一次任务即可拿到机房侧的写入速度。

## 令牌有效期（两个令牌别混）

| | 有效期 | 存在哪 |
|---|---|---|
| **access token** | **1 小时，不可延长** | 不存。`token_from_secret()` 每次运行现换一个 |
| **refresh token** | 生产状态下基本永久 | Colab / Kaggle Secrets，名字 `DRIVE_OAUTH_JSON` |

所以两个平台都能长期有效——前提是 Secrets 里放的是 **refresh token**，不是 access token。
`scripts/measure_drive_write.py --use-access-token` 那条路只适合一次性测量：它签发的短期令牌
一小时后失效且无法续期，每跑一次都要重签。

refresh token 失效的全部原因（developers.google.com 原文 "A refresh token might stop
working for one of these reasons"）及本项目是否适用：

| 原因 | 适用吗 |
|---|---|
| 用户主动撤销授权 | 不撤就不会 |
| **连续 6 个月未使用** | ⚠️ 唯一需要留意的；管道定期跑就碰不到 |
| 改密码且令牌含 **Gmail** 范围 | 否——本项目只有 `drive.file` |
| 同意屏幕为 **Testing** → 7 天过期 | 否——已发布到生产（第 2 步） |
| 超过单账号单客户端 100 个活跃令牌 | 否，但要理解口径 |

最后一条的口径是**每个谷歌账号 × 每个 OAuth 客户端 100 个**。100 个账号各持 1 个令牌毫无问题；
会踩到的是**反复重新授权同一个账号**超过 100 次——每次授权都签发新令牌，超限时最老的会被
静默作废，不给任何提示。批量接账号时如果脚本出错重试，注意别对同一账号反复走授权流程。

## 常见故障对照

| 现象 | 原因 | 处理 |
|---|---|---|
| `invalid_grant` | refresh token 过期 | 同意屏幕仍在 Testing 模式(7 天过期)→ 回第 2 步发布 |
| `401 missing authentication credential` | 没带令牌 | 无令牌时这是**正常**应答;若已配密钥则检查 Secrets 名字是否为 `DRIVE_OAUTH_JSON` |
| `403 insufficient scope` | 范围不对 | 同意屏幕里加上 `drive.file`,然后**重新授权**该账号(改范围后旧令牌不会自动升级) |
| Kaggle 任务产出空、无报错 | 联网被关 | 本项目派发的 kernel 已强制 `enable_internet: true`;若手工建的 notebook 要自己开 |
| 文件上传了但云盘里找不到 | `drive.file` 的正常表现 | 该范围下只能看见本应用创建的文件;在云盘网页端按文件名搜,或看 `result.json` 里的 `folder_id` |
| `(invalid_grant) Missing code verifier.` | PKCE 校验串没带过来 | 已修（verifier 随 state nonce 一起暂存）；若自行改动 OAuth 代码需保留这一点 |
| Colab worker 报 `drive_rest` 导入失败 | 拉取模块失败 | worker 启动时从 `/api/worker/drive_rest` 取该模块,需要 `API_BASE` 是 Colab 能访问的公网地址,`localhost` 不行 |
