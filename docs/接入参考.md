# 外部服务接入参考

记录本项目实际接入的每个外部服务：真实端点、鉴权方式、**实测验证过的**限额，以及踩过的坑。

所有"实测"标注的内容都是在本项目中真实调用验证过的，不是抄文档。文档链接附在每节末尾，用于核对最新变化。

---

## 1. Gemini（Google AI Studio）

| 项 | 内容 |
|---|---|
| 接入方式 | `google-genai` SDK（不是已废弃的 `google-generativeai`） |
| 代码位置 | `backend/quant_ai_bridge.py`（密钥池）、`backend/gemini_probe.py`（实测探测） |
| 鉴权 | API Key，环境变量 `GEMINI_API_KEY` 或 `GEMINI_API_KEYS`（逗号分隔） |
| 获取 | https://aistudio.google.com → API Keys |

### 关键事实（实测 + 官方文档核对）

**没有查询剩余额度的接口。** Google 不提供任何 endpoint 返回"你还剩多少次调用"，API 响应里也不含档位字段。想知道真实上限，唯一途径是**触发 429**——错误报文里会指明具体的配额指标和数值。

**档位由结算账户决定，不由订阅决定：**

| 档位 | 达成条件（官方原文） |
|---|---|
| Free | Active project or free trial |
| Tier 1 | **Set up and link an active billing account** |
| Tier 2 | Paid $100 + 3 days from first successful payment |
| Tier 3 | Paid $1,000 + 30 days from first successful payment |

⚠️ **消费级 Gemini / Google One 订阅不会给 API 项目开通额度。** 买了 Gemini Pro 年费套餐，API 项目依然在 Free 档，除非单独关联结算账户。

### 踩过的坑

- 免费档约 1500 次/天/密钥。用多个免费账号的 key 轮询规避配额，属于规避使用限制，Key 或账号可能被封 —— 对外服务不要依赖这个。
- 面板里的「实测密钥」按钮会对每个 key 发起一次真实调用并原样回显 Google 的响应，包括 429 的完整配额报文。

文档：https://ai.google.dev/gemini-api/docs/rate-limits

## 2. Google Colab

**没有公开 API。** 免费版不提供任何接口用于提交任务、查询配额或管理运行时。

这直接决定了架构：**任务无法被推送给 Colab，只能由 Colab 主动来拉。** 见 `notebooks/colab_worker.py` —— worker 轮询后端领取任务，所有请求都是出站的，这是免费运行时唯一可行的形态。

### 官方限制（FAQ 原文核对）

- 免费版单次会话**最长 12 小时**，"取决于可用性和你的使用模式"
- 空闲会超时断开；关闭浏览器标签页即断
- 本地磁盘每次会话结束**全部清空** —— 要留的东西必须写进云盘
- 原话："资源不保证、不无限，用量限制有时会浮动" —— **刻意不公布配额数字，也没有查询接口**

### 使用限制（会被封的行为）

官方禁止清单包含：文件托管、媒体服务、**与 Colab 交互式计算无关的网络服务**、种子下载、连接远程代理、挖矿、破解密码。

本项目的 worker 做的是数据处理，不在禁止清单内。但官方明确"Colab 优先保障交互式计算"，长时间无人值守的后台任务**可能被终止**。把它当尽力而为的免费算力，不要当成能对外承诺可用性的基础设施。

### 面板能显示什么

既然配额查不到，面板只显示 worker 实测上报的真实值：vCPU 数、内存、可用磁盘、GPU、以及**已运行时长 / 12 小时上限**。已运行时长是唯一有意义的进度条。

文档：https://research.google.com/colaboratory/faq.html

## 3. Google Drive

| 项 | 内容 |
|---|---|
| 接入方式 | `google-api-python-client` |
| 代码位置 | `backend/google_account_manager.py` |
| 鉴权 | OAuth 2.0，客户端密钥存 `backend/data/credentials.json` |
| Scope | `https://www.googleapis.com/auth/drive` |

### 踩过的坑

**`urn:ietf:wg:oauth:2.0:oob` 已被 Google 废弃。** 原代码默认用这个复制粘贴授权码的流程，新建的 OAuth 客户端根本用不了。现已改为回环重定向：

```
http://localhost:8000/api/accounts/oauth/callback
```

创建 OAuth 客户端时类型选 **Web application**，并把上面这个地址加进"已授权的重定向 URI"。部署到其他地址时用 `PUBLIC_BASE_URL` 环境变量同步修改。

**每日传输配额查不到。** `about().get(fields="storageQuota")` 只返回已用存储总量，**不返回**每日 750GB 上传 / 10TB 下载的滚动用量。所以面板里的传输进度条是本平台**自行统计**的，只覆盖经由本平台发生的传输，平台外的操作不计入 —— 这一点在界面上有明确说明。

**FUSE 挂载不支持 POSIX flock。** 云盘挂载目录只能放只读 `.parquet`，绝不能在上面创建或修改数据库文件。

### 性能注意

Drive 没有可靠的 range request 支持，且限流激进。**不要让 DuckDB 直接查询云盘挂载路径** —— 大表扫描会从秒级劣化到分钟级。云盘只当冷归档，热数据放本地 NVMe。

## 4. 币安公开数据

| 项 | 内容 |
|---|---|
| 端点 | `https://data.binance.vision/data/spot/monthly/klines/{SYMBOL}/{INTERVAL}/{SYMBOL}-{INTERVAL}-{YYYY-MM}.zip` |
| 鉴权 | **无需** |
| 限额 | **无** |
| 代码位置 | `backend/binance_ingestion.py` |

### 实测数据

- BTCUSDT 1分钟线，单月约 2.2 MB（zip），44640 行（31天 × 1440）
- CSV **无表头**，12 列，顺序：`open_time, open, high, low, close, volume, close_time, quote_volume, trade_count, taker_buy_volume, taker_buy_quote_volume, ignore`

### 踩过的坑

**时间戳是微秒不是毫秒。** 新版归档用 16 位微秒时间戳（如 `1735689600000000`），旧版是 13 位毫秒。同一个交易对不同月份可能不一致，所以代码按数值量级逐行判断，不假定统一格式。

当月归档要等月份结束才发布，因此拉取时会跳过当前月。

## 5. Hypersync（Envio）

| 项 | 内容 |
|---|---|
| 接入方式 | `hypersync` SDK ≥1.0 |
| 代码位置 | `backend/hypersync_ingestion.py` |
| 鉴权 | `HYPERSYNC_API_TOKEN`（≥1.0 的新名称）或 `HYPERSYNC_BEARER_TOKEN`（旧名，仍兼容） |
| 获取 | https://app.envio.dev/api-tokens |

**无令牌一律 401。** 不存在免注册的匿名访问档位，实测确认。

链地址：`https://eth.hypersync.xyz`、`bitcoin` / `polygon` / `arbitrum` / `optimism` / `bsc` 同构。

用 `collect_parquet()` 直接流式落盘，不要手动转 Arrow。

## 7. AWS 公开区块链数据集（**尚未接入**）

已验证可用，但**还没有写任何代码**。

| 项 | 内容 |
|---|---|
| 端点 | `https://aws-public-blockchain.s3.us-east-2.amazonaws.com/` |
| 前缀 | `v1.0/btc/`、`v1.0/eth/` |
| 鉴权 | **无需**，匿名可下（实测 HTTP 200） |
| 格式 | Parquet（snappy），按 `date=YYYY-MM-DD` 分区 |
| 以太坊表 | `blocks`、`transactions`、`logs`、`traces`、`token_transfers`、`contracts` |

### 实测数据（重要）

**以太坊单日 transactions 表 = 832 MB。** 这一个数字决定了全量镜像不可行：

- 按实测下载速度约 1.5 MB/s，拉完 20TB 需要**约 154 天不间断**
- 即使跑到 10 倍速，仍需 15 天
- 而这还只是一张表、一天的数据；traces 通常是 transactions 的 5~10 倍

**结论：按需拉取你要回测的部分，不要做全量镜像。**
